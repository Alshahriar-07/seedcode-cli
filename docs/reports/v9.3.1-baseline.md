# Seed Code CLI v9.3.1 — Repository Baseline Audit

**Environment:** Windows 11 (10.0.26300), Python 3.12.10, pytest 8.4.2
**Commit at audit:** `2084b89` (Release v9.2.1)
**Baseline command:** `python -m pytest -q`
**Baseline result:** `833 passed in 79.90s`

This report records what was actually observed before any change. All plan
documents in `SeedCode-CLI-v9.3.1-Update-Plan/` were read first.

## 1. Reported startup failure — reproduced and root-caused

`seedcode/cli.py` used three symbols it never imported or defined:

| Line | Reference | Reality |
|---|---|---|
| 139 | `ensure_workspace(interactive=...)` | Defined at `seedcode/workspace.py:283`; **not imported** by `cli.py` |
| 145 | `UI(plain=terminal.plain)` | `terminal` module/object **does not exist**; terminal detection lives in `seedcode/utils/terminal_env.py` |
| 147 | `_use_persistent_tui(terminal.plain)` | same undefined `terminal` |

`python -c "import seedcode.cli"` succeeds because the names are only resolved
inside `main()`. The first real launch therefore fails with
`NameError: name 'ensure_workspace' is not defined` before the UI is built — in
a source checkout, a pip install and a PyInstaller EXE alike.

The workspace initializer was **not missing**: `ensure_workspace()` has a real
implementation (environment override → explicit prompt → current folder) and is
covered by its own tests. The defect is the missing import, so no stub was
added and no workspace behavior was changed.

Why the 833-test baseline did not catch it: the existing CLI tests exercise
`--version` / `--help` (which return early) or patch the app layer; none ran
`main()` past terminal-title setup into workspace selection.

## 2. Architecture found in the repository (not rebuilt)

The update plan's target architecture already exists in substance; the audit
therefore repaired the broken entry point rather than duplicating it:

- **Orchestration / TODO:** `seedcode/core/session.py` (`CodeSession`, resume at
  line 972) and `seedcode/core/tasks.py` (`TaskGraph` at line 413, states
  including `PENDING/IN_PROGRESS/COMPLETED/FAILED/RECOVERING/BLOCKED/CANCELLED`,
  evidence and retry tracking). One-subtask-at-a-time execution and
  evidence-gated completion are enforced there.
- **Session context:** persistent checkpoints, summaries and restore/resume in
  `core/session.py` / `memory/`.
- **Tools:** registry in `seedcode/tools/__init__.py`; file, search, terminal,
  git and permission modules under `seedcode/tools/`; native + text-protocol
  tool parsing and dispatch in `core/agent.py`.
- **UI:** `seedcode/ui/tui.py`, `taskpanel.py`, `state.py` (chat/activity on the
  left, plan panel right, thinking panel above the input).
- **Providers:** `core/providers/` contains `ollama.py`, `ollama_start.py`,
  `openrouter.py`, `custom.py`, `default.py`, `failover.py`, `health.py`;
  bounded retry and external/owned process handling exist there.
- **Packaging:** `IRM_INSTALL/install.ps1`, `install.sh`, `npm/`,
  `scripts/windows/build.bat`, `setup.iss`, `stage_release.py`, and the GitHub
  release workflow.

These areas were inspected, not rewritten. Their existing tests remain green.

## 3. Other defects found

- `seedcode/cli.py` had no trailing newline (cosmetic, fixed).
- Version metadata was `9.2.1` everywhere; the v9.3.1 release required a
  coordinated bump (package, npm, IRM scripts, Setup script, docs, tests).
- `scripts/bump.py` is a one-line non-functional file
  (`__import__("open")`); it is not referenced by the build or tests and was
  left untouched rather than replaced without a requirement.
- Build environment: PyInstaller 6.21.0, `build` 1.5.0, Node 24.15.0 and npm
  11.12.1 are available. **Inno Setup (ISCC.exe) is not installed**, so the
  Setup EXE cannot be produced in this environment.

## 4. Baseline test inventory

833 tests passed at baseline. The completion phase added 7 regression tests
(`tests/test_v931_startup.py`, 4; `tests/test_v931_npm.py`, 3), for a final
**846 passed** (including 6 installer-UI tests). No test was deleted, skipped or weakened to obtain a pass.

## 5. Completion-phase findings (after the initial audit)

- **Inno Setup 6 was present after all**, under
  `%LOCALAPPDATA%\Programs\Inno Setup 6\ISCC.exe`. The initial audit only
  searched Program Files, which is why the Setup EXE was first reported as
  blocked. It was subsequently compiled, installed, verified and uninstalled.
  Inno 6 rejects `--define=` (Inno 7 syntax), so the build must use `/D`
  switches; `scripts/windows/build.bat` already has that fallback.
- **npm launcher defect:** `npm/lib/download.js` called
  `assetName(artifact)` where `assetName(version, platform)` was expected, so
  the launcher raised `no prebuilt asset for undefined` before downloading.
  Fixed with a single `artifactFileName()` helper used by the cache path, the
  checksum lookup and the URL; covered by `tests/test_v931_npm.py`.
- **Installer data-safety hardening:** a silent uninstall now keeps
  `~/.seedcode` unconditionally (no prompt is possible under `/VERYSILENT`).
  Verified with a canary file that survived the uninstall.

## 6. Final state

All seven required release files exist in `dist/release/v9.3.1/`, `sha256sum -c`
passes for all five binary/source artifacts, the full suite reports 840 passed,
and the manifest records `build_status: complete`. Live provider tests and an
end-to-end IRM install against a published release remain unperformed (no
Ollama server, no provider credentials, no publishing authorization).
