Developer fallback:                        python -m seedcode

WHAT CHANGED IN v10.2.1
----------------------
v10.2.1 is a reliability and interface-polish release: the coding agent now
guarantees real workspace changes, the terminal interface is quieter, and one
long-standing timestamp annoyance is gone.

  * Minimal thinking display. The bottom strip is now just a small dim
    "Thinking..." label above the reasoning summaries the connected model or
    provider actually exposes. The former full-width "LIVE AI BRIEFING"
    dashboard - title, model/provider identity, status fields, LIVE badges -
    is gone. The strip hides when there is no reasoning, keeps a compact
    bounded height, follows the newest update automatically, and preserves the
    completed reasoning after the turn. A provider that exposes no reasoning
    shows the honest line "Reasoning stream unavailable for this model.";
    nothing is ever fabricated.

  * No timestamps beside AI responses. The activity log no longer prefixes
    each line with a bracketed [HH:MM:SS] wall-clock stamp; that prefix was
    the timestamp appearing next to streamed answers. Timestamps remain in
    the backend activity events for logs and debugging.

  * Guaranteed real workspace execution. File-modification tasks can no
    longer complete on a printed claim: completion is gated on observed
    evidence (the file really created/changed, the command really run), the
    agent is re-instructed when the work was only described, and the prompt
    now carries explicit rules - code belongs in files, a printed tool call
    is not an executed tool call, chat output is not file output.

  * File tools hardened.
      - read_file refuses probable binaries instead of dumping mojibake, and
        supports line ranges for large files.
      - Every write (write_file, edit_file, insert_in_file, append_file) is
        atomic: temp file -> flush -> fsync -> replace, so an interruption
        cannot leave a truncated file, and a binary file is never silently
        overwritten with text.
      - edit_file supports an explicit replace_all for several independent
        occurrences while still rejecting ambiguous single replacements.
      - search_text gained ignore_case and exclude filters, path globs are
        path-aware ('src/*.py' is one level; 'src/**/*.py' recurses), and the
        workspace walker honors .gitignore.

  * Read-only tasks are understood, not punished. Research, explanation and
    review tasks can finish verified from real read-only inspection shared
    with the task, while any task that says it must modify files stays gated
    on real file evidence.

  * TODO/plan panel improvements carried in this release line: hierarchical
    plans keep their nesting, dependencies schedule dependency-first, crashed
    or repeated failures cannot be marked complete, and the panel always
    reflects backend state.

INSTALLATION METHODS
--------------------

1) Windows - remote PowerShell installer (recommended on Windows)

     irm https://seedcode-cli.vercel.app/install.ps1 | iex

   Downloads the official SeedCode-CLI-10.2.1-windows-x64.exe from GitHub
   Releases and verifies its SHA-256 against the release's SHA256SUMS.txt. A
   mismatch, a missing entry, or an unreachable checksum file aborts;
   verification is never bypassed. It installs per-user to
   %LOCALAPPDATA%\Programs\SeedCode, adds that directory to the user PATH, and
   verifies the installed binary reports version 10.2.1. PowerShell 5.1 and 7+
   compatible; ANSI UI with graceful fallback; Ctrl+C safe.

2) Windows - Setup installer

   Download SeedCode-CLI-Setup-10.2.1.exe from
   https://github.com/Alshahriar-07/seedcode-cli/releases/tag/v10.2.1 and run it.
   Installs with a Start Menu shortcut and adds the install directory to the
   PATH so `seedcode` works in new terminals. Preserves configuration during
   upgrades (user config lives in the Seed Code config directory, not the
   install directory).

3) Windows - portable executable

   Download SeedCode-CLI-10.2.1-windows-x64.exe from the releases page and
   run it directly. No installation, no PATH changes; `seedcode --version`
   reports 10.2.1. For a persistent `seedcode` command, use method 1 or 2.

4) Linux / macOS - remote shell installer

     curl -fsSL https://seedcode-cli.vercel.app/install.sh | bash

   Downloads the official SeedCode-CLI-10.2.1-<os>-<arch> standalone binary
   from GitHub Releases when the release publishes one for this platform, and
   otherwise downloads the official seedcode_cli-10.2.1-py3-none-any.whl. Either
   way the downloaded file's SHA-256 is verified against the release's
   SHA256SUMS.txt before anything is installed (a mismatch aborts, and an
   unreachable checksum file aborts too - verification is never bypassed).
   Installs to ~/.local/bin and verifies the installed binary reports 10.2.1.
   pipx is used for the wheel when available (otherwise pip --user, with
   PEP 668 handling). Clean ANSI UI with ASCII fallback; Ctrl+C safe.

5) Any OS - pip

     pip install seedcode-cli

   Then run:

     seedcode          (primary command)
     python -m seedcode   (developer fallback)

   First launch initializes the per-user configuration in the Seed Code
   config directory (never inside site-packages) and prompts for a provider
   and model. The wheel requires Python 3.10+.

INSTALLER EXPERIENCE
--------------------
Both remote installers share one monochrome Seed Code UI: a compact banner,
seven real installation stages, stage-accurate progress and actionable errors.
Download, checksum and version verification are unchanged.

  - Progress reflects real stages (no invented percentages).
  - Long operations show real spinners, or the downloader's own byte progress.
  - Redirected output, NO_COLOR, --plain and TERM=dumb disable animation.
  - Errors report a reason, a suggested action and a stable error code.
  - The success screen appears only after the installed binary reports 10.2.1.

UPGRADE SAFETY
--------------
Upgrades preserve user configuration and provider/API settings. The Windows
installers upgrade in place; configuration lives in the Seed Code config
directory and is never deleted by an installer.

CHECKSUMS
---------
Every release artifact has a SHA-256 entry in SHA256SUMS.txt:

  cd dist/release/v10.2.1
  sha256sum -c SHA256SUMS.txt            # Linux/macOS
  Get-FileHash <file> -Algorithm SHA256  # Windows

Both remote installers verify before installing: they read the release's
SHA256SUMS.txt as the authoritative expected value and abort on any mismatch
or a missing entry. If the checksum file is unreachable, the install aborts
rather than proceeding unverified - verification is never bypassed. All
digests are computed from the final published artifacts; none are invented.
